FreeTubium can now **play** video, not just download it. This release adds a Watch page that plays videos and playlists inside the app, plus optional YouTube sign-in that applies to downloads as well as watching.

## Downloads

Pick the installer for your platform:

| Platform | File |
| --- | --- |
| Windows 10 / 11 (x64) | `FreeTubium_0.2.0_x64-setup.exe` (recommended) or `FreeTubium_0.2.0_x64_en-US.msi` |
| macOS (Apple Silicon) | `FreeTubium_0.2.0_aarch64.dmg` |
| macOS (Intel) | `FreeTubium_0.2.0_x64.dmg` |
| Linux (x64) | `FreeTubium_0.2.0_amd64.AppImage` or `FreeTubium_0.2.0_amd64.deb` |

## New: the Watch page

- Paste a video or playlist link and watch it without opening a browser
- A playlist becomes a play queue that auto-advances, with a click-to-jump list and per-item duration
- Videos play in YouTube's own player, so views and ads count normally
- Anything that player refuses - age-restricted, members-only, or embedding-disabled - falls back **per item** to a local player that extracts the video with the bundled `yt-dlp`
- Both players support full seeking
- Save whatever is playing to the download queue in one click
- Completed downloads get a **Watch** action on the History page that plays the file straight from disk, with nothing to fetch

## New: optional YouTube account

Age-restricted, members-only, and private videos need an account. `yt-dlp` can only authenticate with cookies, so Settings -> **YouTube account** offers three ways to supply them:

- Sign in inside the app, which captures that session's cookies
- Read cookies from a browser you are already signed into
- Import a `cookies.txt` exported by a browser extension

This is **off by default**. It applies to downloads as well as watching, so signing in once unlocks restricted videos everywhere in the app.

Two things worth knowing before you opt in, both from `yt-dlp`'s own guidance:

- Using your account this way risks YouTube temporarily or permanently restricting it, so prefer a throwaway account
- Reading cookies from a browser does not work with Chrome 127 and later, which encrypt their cookie store - use Firefox for that option

YouTube also rotates cookies over time. When a saved session stops working, FreeTubium now recognises the failure and points you at the setting that fixes it instead of showing a bare extractor error.

## Fixes

- Release notes are published from the repository as UTF-8, so they no longer render as gibberish in the GitHub mobile app
- Release builds retry sidecar downloads and fall back to a mirror for the Linux `ffmpeg`, so a flaky network no longer fails a whole build

## Note on security warnings

These builds are **not code-signed**, so your OS will warn on first launch:

- **Windows SmartScreen:** click **More info -> Run anyway**
- **macOS Gatekeeper:** right-click the app -> **Open**, then confirm

Nothing is wrong with the download - the OS simply cannot verify who built it. If you prefer, [build from source](https://github.com/TheEvalon/FreeTubium#development).
